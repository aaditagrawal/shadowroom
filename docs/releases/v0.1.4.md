Shadowroom v0.1.4 reduces Linux desktop dependencies while preserving the established color management and codec defaults.

- Linux folder, import/backup destination, export and theme pickers now run inside Shadowroom. Directory reads happen in the background. Ctrl+L edits the path, Tab selects the entry list, Enter opens an entry, Ctrl+Enter confirms, and Escape cancels.
- Linux OS Trash writes FreeDesktop Trash storage directly, without loading GIO. It preserves restore metadata and handles collisions and non-UTF8 filenames. Unsafe storage or unsupported atomic moves produce an error; there is no permanent-deletion fallback. Optional drive ejection still uses `gio mount -e`.
- Ingest uses the kernel's atomic rename operation without importing the newer glibc wrapper. Portable Linux packaging now checks all packaged ELF binaries and libraries against the glibc 2.28 baseline before creating an archive.
- Preview caches distinguish rendering backends and server configurations. Local rendering variants share one disk quota; remote renderer identities persist across offline restarts.
- Dialog selections have visible outlines, and button hover feedback remains visible on elevated surfaces.

Experimental Rust ICC and HEIC backends are available through build features. LittleCMS and the existing native codecs remain enabled by default. CMYK interpolation differs in the Rust ICC backend, higher-depth HEVC needs further real-file coverage, and full sensor RAW rendering still uses LibRaw.

The source includes a separate read-only CPU/X11 browsing prototype and a reproducible musl build helper. Its static executable was checked for absence of shared-library/glibc requirements, run in AlmaLinux 8 and Debian 11 userspaces, and opened grid/loupe windows on X11. It is not the full desktop app and is not included as a supported release executable. Containers share the host kernel; older-kernel support has not been established.

The full portable Linux AppImage/archive remains x86_64 with glibc 2.28 or newer and requires a compatible desktop session and Vulkan driver. macOS archives remain arm64, signed ad hoc and not notarized. Fedora 44 RPMs use system libraries/codecs. No universal older-Linux compatibility claim is made.

Validation covered lean, native and experimental Rust media configurations; desktop/prototype tests; packaged folder/theme selection; decisions, persistence, restart/close barriers and exports; confirmed OS Trash; and actual AppImage launch without FUSE. Original bytes and timestamps were verified in native acceptance checks. Release CI builds and checks each platform artifact before publication.

See [Linux portability](https://github.com/aaditagrawal/shadowroom/blob/v0.1.4/docs/PORTABILITY.md) for build features, measured gaps and further compatibility work, and [Fedora distribution](https://github.com/aaditagrawal/shadowroom/blob/v0.1.4/docs/FEDORA.md) for COPR installation and update instructions.
