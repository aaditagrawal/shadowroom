Shadowroom v0.1.2 refines Catalog review entry, adds image actions, and makes deletion an explicit choice between OS Trash, in-app Trash, and permanent removal.

- In Catalog, Enter/L opens the current collection at the hovered or active photo when zero or one photo is selected. Selecting multiple photos before Enter/L limits Review to that set. Double-click and Show in review always open the full current collection. Returning to Catalog restores its selection.
- Right-click photos for Show in folder, Show in review, Survey burst, Compare, Pick, Reject, Reset, Move to Trash, and permanent deletion. Right-click a member of a Catalog selection to retain that batch, or another photo to target it instead.
- Delete defaults to the operating system's Trash. Preferences → Culling → Trash destination retains optional in-app Trash, which leaves originals in place and supports Restore/Undo. Existing in-app Trash decisions are preserved; changing modes does not move those files.
- Shift+Delete requests permanent local-file deletion. Every UI deletion opens a frozen confirmation with photo/file counts, source locations, and the destination/recovery route. Cancel is selected initially: Enter cancels; Tab then Enter confirms; Escape cancels.
- Physical deletion includes RAWs, paired companions, and recognized adjacent sidecars. Changed files are refused, unavailable OS Trash never silently falls back to permanent deletion, and partial outcomes remain visible. Restore OS-trashed files with your file manager. Physical deletion cannot be undone in Shadowroom and clears old decision Undo history after files change.
- Apply commits preferences and keeps the pane open; Apply & Close commits and closes. Cancel/Escape discards only unapplied changes since the last Apply.
- The MCP `trash` tool remains app-only regardless of the UI preference. Physical deletion requires confirmation in the app and is unavailable for remote photos. Ratings, flags, and labels still use the catalog/recovery model; XMP writes remain an explicit export.
- Fedora publication now submits the checksum/provenance-verified release source RPM to `aaditagrawal/shadowroom` COPR after native checks and GitHub publication. Existing release builds are reused instead of duplicated; the job reports the COPR result separately from GitHub release availability.

The [darktable comparison](https://github.com/aaditagrawal/shadowroom/blob/v0.1.2/docs/DARKTABLE.md) records the official stable manual and pinned-source findings behind these design choices, including how Shadowroom's confirmations differ.

Choose the asset for your platform. Linux AppImages target x86_64 with glibc 2.28 or newer and bundle the documented RAW/HEIF codecs; a compatible desktop session and Vulkan driver remain required. OS Trash on Linux uses GIO (`glib2` on Fedora) and reports unavailable support without permanent-deletion fallback. macOS archives are arm64, signed ad hoc, and not notarized. The Fedora 44 x86_64 RPM uses system libraries and optional system codecs; installing a downloaded RPM does not configure automatic updates. Each release executable/archive includes a matching SHA-256 checksum. See the source tree's build, media, and Fedora guides for details.

After the [COPR build](https://copr.fedorainfracloud.org/coprs/aaditagrawal/shadowroom/) succeeds for Fedora 44 x86_64, repository installs and updates use:

```sh
sudo dnf copr enable aaditagrawal/shadowroom
sudo dnf install shadowroom
sudo dnf upgrade shadowroom
```
